# Implementation Plan

## Strategy

実装は **DB → 純関数 → Service/Hook → 台帳 UI → シフト表バッジ → LINE 通知ジョブ** の順に積み上げる。配車ボード（orders）には触れない。既存シフト表・日次締めの見た目・ロジックは変更せず、挿入点のみ追加する。

> **Parallel marker**: ` (P)` 付きはファイル境界が独立で並行実装可。

---

## 1. データベース基盤

- [x] 1.1 予約台帳と通知ログのスキーマを追加する
  - `reservations`（予約日時・顧客名・電話・メモ・作成/更新日時）と `reservation_day_notifications`（notify_date PK・skipped・送信ログ）を作成
  - `reserved_at` / 顧客名・電話の索引、`updated_at` トリガー、RLS（読取は anon+authenticated、書込は authenticated）を付与
  - 配車テーブルとの FK・トリガーは作らない（データ分離）
  - _Requirements: 1.2, 1.4, 1.5, 1.6, 3.3, 4.4, 8.1, 8.2, 8.4_

---

## 2. 純関数（日時ウィンドウ・LINE 本文）

- [x] 2.1 (P) 営業夜ウィンドウと暦日範囲の算出を実装する
  - Asia/Tokyo で実行日 D の `[D 19:00, (D+1) 06:00)` 境界を返す
  - 台帳・シフト用の暦日 `[D 00:00, (D+1) 00:00)` 範囲も返す
  - 境界・日付跨ぎのユニットテストを含める
  - _Requirements: 5.1, 6.1_
  - _Depends: なし（1.1 と並行可）_

- [x] 2.2 (P) スタッフ向け LINE 本文生成を実装する
  - ヘッダ・各予約（時刻・氏名・電話・メモ要約）・件数超過時フッター
  - 長文・多数件の截断ルールをテストで固定
  - _Requirements: 6.2_
  - _Depends: なし（2.1 と並行可）_

## 3. データアクセス層

- [x] 3.1 予約の一覧・月次取得・登録・更新・削除の Service を実装する
  - `{ data, error }` 形式。必須項目欠落は保存前に拒否
  - 日付・キーワード（氏名/電話の部分一致）フィルタ、物理削除
  - orders / dispatch_slots への副作用なし
  - _Requirements: 1.2, 1.3, 1.5, 1.6, 2.3, 2.4, 3.1, 3.2, 3.4, 4.2, 8.1_
  - _Depends: 1.1_

- [x] 3.2 クエリキーと React Query Hook（取得/mutation・invalidate）を追加する
  - フィルタ一覧・月次・詳細、作成/更新/削除後に関連キーを無効化
  - _Requirements: 2.1, 3.3, 5.1_
  - _Depends: 3.1_

## 4. 予約台帳画面と導線

- [x] 4.1 (P) 台帳ページ（一覧・空状態・日付/検索フィルタ・詳細表示）を実装する
  - 予約日時昇順。各行に日時・氏名・電話・メモ要約
  - `?date=` で日付フィルタ初期化（シフト表からの遷移用）
  - 新規 CSS のみ。既存画面のレイアウト/配色は変更しない
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 7.3_
  - _Depends: 3.2_

- [x] 4.2 (P) 新規登録・編集ダイアログと削除確認を実装する
  - 必須: 予約日時・顧客名・電話。メモ任意
  - 保存失敗時は入力を保持してエラー表示。削除は確認後のみ
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 3.1, 3.2, 3.4, 4.1, 4.2, 4.3_
  - _Depends: 3.2（4.1 と並行可）_

- [x] 4.3 ナビとルートを接続し、書込を認証保護する
  - `/reservations` を追加。ナビから到達可能。未認証は既存方針どおり保護（書き込み不可/ログイン誘導）
  - _Requirements: 7.1, 7.2_
  - _Depends: 4.1, 4.2_

## 5. シフト表への予約表示

- [x] 5.1 日付ヘッダに件数バッジと一覧ポップオーバーを追加する
  - 表示中日付に予約が 1 件以上なら件数バッジ。0 件は非表示
  - クリックで時刻・顧客名一覧。台帳（日付付き）へのリンク
  - シフトデータは変更しない。`day-header-date-row` への最小追加のみ
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_
  - _Depends: 3.2（4 系とファイル競合が無ければ並行可だが、バッジは月次 Hook 依存のため 3.2 完了後）_

## 6. 予約当日スタッフ LINE 通知

- [x] 6.1 通知 Edge Function（認可・冪等・0 件スキップ・LINE リトライ・失敗メール）を実装する
  - `CRON_SECRET` Bearer。営業夜ウィンドウの予約を取得
  - 既送は skip（`force` で再送可）。0 件は送信せず `skipped=true` で記録
  - LINE 最大 3 リトライ。失敗時は日次締めと同方針でメールアラート
  - 既存 `LINE_GROUP_ID` のみ。顧客個別送信は入れない
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 8.2, 8.3_
  - _Depends: 1.1, 2.1, 2.2_

- [x] 6.2 (P) 19:00 JST cron 呼び出し用の設定スニペットをリポジトリに追加する
  - UTC `0 10 * * *` で本 Function を叩く例（既存 daily-close 設定と同型）
  - デプロイ手順そのもののオーナー作業はタスク外。コード側の設定雛形のみ
  - _Requirements: 6.1_
  - _Depends: 6.1 のエンドポイント名が決まっていれば並行記述可。無ければ 6.1 後_
