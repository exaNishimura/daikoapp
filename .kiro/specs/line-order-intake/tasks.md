# Implementation Plan

## 1. 基盤・設定・スキーマ

- [x] 1.1 LINE 受注の正本テーブルと設定テーブルを追加する
  - ヘッダ／台単位／設定／電話優先ロック／通知冪等ログを永続化する
  - 台単位に hold_until・uses_extra_capacity・order/reservation リンク・ステータスを持たせる
  - 割引設定を拡張可能な JSON として初期値 FIXED_YEN 500 を入れる
  - _Requirements: 4.1, 5.2, 6.1, 6.2, 6.3, 6.4, 9.1, 9.2, 9.3, 3.1_

- [x] 1.2 共有 PIN の安全な保存と検証手段を用意する
  - 平文保存せずハッシュ化して設定に保持する
  - 検証失敗時に承認させない／失敗回数制限の方針を実装する
  - _Requirements: 5.1, 5.2, 5.5, 5.7_

- [x] 1.3 Messaging クライアントを顧客 userId とグループの双方に対応させる
  - 既存トークン／GROUP_ID を再利用し push・リトライ・失敗アラート方針を揃える
  - Webhook 署名検証とグループ発言の誤処理防止を入れる
  - Secrets に CHANNEL_SECRET／LIFF_ID を追加する手順をコード側で参照可能にする
  - _Requirements: 10.1, 10.2, 10.3, 10.4, 8.4_

## 2. 可否判定エンジン

- [x] 2.1 営業日・稼働台数・仮想余裕枠の設定を読み可否に反映する
  - 平日／金土想定台数と max extra（+1〜+2）を設定から読む
  - 当日は extra なし、事前は extra 可、要手配フラグを返す
  - 実車両マスタを増減しない
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7_

- [x] 2.2 Maps 所要＋バッファと配車表・予約台帳突合を共有ロジック化する
  - 既存最短枠探索を Edge／SPA 共用できる形へ寄せる
  - 現行バッファ実装が 0 でないか確認し、要件どおりバッファ込みにする
  - Edge から Directions を直呼びできる経路を用意する
  - _Requirements: 2.2, 2.8, 2.9_

- [x] 2.3 電話優先ロックと営業時間外「今すぐ」拒否を実装する
  - 確保／否決帯を LINE 不可にする
  - ホールドより電話優先
  - 営業外の今すぐは日時指定を促して拒否
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 2.10_

## 3. 受付 API・仮受付・ホールド

- [x] 3.1 LIFF からの申込受付 API を実装する
  - userId・住所・日時・車両・電話・複数台を受け仮受付を作成する
  - 可ならグループ承認依頼と顧客仮受付完了を送る
  - 不可なら顧客に結果を返す
  - _Requirements: 1.3, 1.5, 1.6, 1.7, 4.1, 4.2, 4.3, 2.9_

- [x] 3.2 ホールド期限の算出と期限切れ処理を実装する
  - 営業時間内は 15 分、それ以外は次の 19:00
  - 期限切れで枠解放、顧客へ失敗＋埋まり可能性通知、グループへ期限切れ通知
  - cron／定期実行で漏れなく処理する
  - _Requirements: 4.4, 4.5, 4.6, 4.7, 4.8_

- [x] 3.3 当日は配車ボード系、非当日は予約台帳系へ投影する
  - 仮受付／確定時にリンクを更新し LINE 経由と分かる印を残す
  - 投影失敗時は正本を残し再試行可能にする
  - _Requirements: 6.1, 6.2, 6.3, 6.4_
